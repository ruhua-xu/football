# 历史数据源研究状态

## 结论

截至 2026-09-01，本阶段没有下载、复制、转换或提交任何第三方历史归档，也没有在仓库中创建第三方原始数据样本。

原因是以下两项准入条件仍未确认：

- 数据许可及原始数据保存、加工、公开再分发的权利边界未确认。
- 数据在历史时点的 `observed_at_utc` / `available_at_utc` 等可用时间来源与证明链未确认。

因此，本文件不对任何数据源作选型、准确性或合规性背书，不声明任何候选来源具有特定许可证，也不以推测值补写许可或历史可用时间。仓库中的 `SYNTHETIC_ACCEPTANCE_DATA` 是确定性合成验收数据，不是第三方历史数据，也不代表真实历史表现。

## 评估标准

第三方数据进入研究样本、adapter 或仓库前，至少需要逐项形成可审计证据：

| 维度 | 准入问题 |
| --- | --- |
| 来源身份 | 数据发布主体、原始入口、数据产品或导出版本能否明确识别？ |
| 许可与条款 | 获取、保存、加工、内部研究、展示和再分发是否分别被允许？适用条款的版本与确认日期是否可留档？ |
| 仓库边界 | 原始 payload、派生字段、checksum、测试摘录分别能否提交到公开仓库？是否要求署名、删除或限制保留期？ |
| 历史可用时间 | 能否证明每条记录在决策 cutoff 前已由来源发布，而不是只知道本地下载时间？时间字段是来源生成、抓取观察、发布还是后补时间？ |
| 修订语义 | 赛程、赔率和赛果更正是否有版本、发布时间及稳定的 supersession 关系？ |
| 覆盖范围 | 目标联赛、赛季、比赛、市场、赔率快照和竞彩固定奖金的覆盖率及缺失分布是否可量化？ |
| 比赛语义 | 常规时间、伤停补时、加时、点球、延期、取消、腰斩和 VOID 是否有明确且可映射的状态定义？ |
| 赔率语义 | 赔率属于开盘、时点快照还是收盘值？时区、庄家、市场、盘口和采集时间是否完整？ |
| 标识与映射 | provider match ID 是否稳定？队名、赛事和场次映射冲突能否人工复核并保留版本？ |
| 完整性 | 是否可保存 source reference、实际下载时间、文件 SHA-256、记录数、字段说明和原始响应版本？ |
| 数据质量 | 是否能拒绝重复业务键、非有限数、非法时区、逆序时间、坏 hash 和不完整更正链，而不是静默修复？ |
| 可复现性 | 相同归档、配置和 cutoff 是否确定性选择相同版本并生成相同 input manifest？ |
| 运维条件 | 鉴权、费用、速率限制、历史深度、服务稳定性和终止订阅后的数据保留权是否明确？ |
| 人工验收 | 小样本能否与来源页面或正式导出逐场核对，并记录核对人、时间、差异和处置？ |

`license_note`、`source_reference` 等 manifest 字段只能保存已经确认的事实；字段存在本身不等于许可或时间来源已经通过审查。

## 候选来源类别

以下仅是后续可评估的来源类别，不构成推荐、授权判断或质量背书：

| 来源类别 | 可评估的数据范围 | 首要核查点 |
| --- | --- | --- |
| 赛事组织方、联赛或足协官方归档 | 赛程、比赛身份、最终赛果和更正 | 历史发布时间、状态语义、下载与再分发权 |
| 官方彩票或其授权数据归档 | 竞彩场次、固定奖金、销售状态和赛果核对 | 授权链、历史快照完整度、计奖口径和公开使用边界 |
| 公共足球数据集或公共 API | 赛程、赛果及基础比赛元数据 | 实际适用条款、历史深度、修订记录和 point-in-time 时间 |
| 商业体育数据与赔率服务 | 赛程、赛果、赔率快照和标识映射 | 订阅范围、原始响应保留权、再分发限制和历史时间证明 |
| 博彩公司或交易市场正式导出 | 特定市场的时点赔率或成交数据 | 市场定义、快照/成交时间、账户条款和再使用权限 |
| 用户或机构提供的授权导出 | 已获许可的 CSV、JSON 或数据库导出 | 权利证明、导出链、字段字典、时间来源和公开提交范围 |
| 学术或研究机构发布的数据集 | 经整理的比赛、赛果、赔率或特征 | 原始来源链、派生许可、引用要求和历史可用时间保真度 |

## 数据模式裁决

- 只有能够证明 `captured/observed <= available <= ingested <= cutoff` 的记录才可进入 `LIVE_STRICT`。
- 后来取得的历史归档只能在来源时间可信时评估 `SOURCE_TIME_RESEARCH`，并必须保留 `retrospective=true`、独立的实际 `imported_at_utc` 和醒目的 `RETROSPECTIVE_SOURCE_TIME_RESEARCH` 报告标签。
- `SOURCE_TIME_RESEARCH` 不是缺失时间来源的绕过机制。无法确认历史可用时间的记录应标记为不满足严格 point-in-time，不得伪造 timestamp。
- 在许可、再分发边界和时间来源同时确认前，不下载第三方样本、不开发真实 adapter，也不生成真实来源回测结果。
