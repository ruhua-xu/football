# 足球竞彩每日分析交接文档

> 用途：将本聊天中已经形成的足球竞彩分析方法、用户偏好、资金结构、对冲思想、复盘教训和项目协作方式一次性交给新的聊天框。
> 新聊天应优先遵守本文件。若与 football 项目中的最新正式架构文件、Schema 或 Strategy Profile 冲突，以项目中的最新正式文件为准。

---

# 1. 项目定位

本项目用于构建和运行个人足球竞彩智能分析与串关决策系统。

核心原则：

1. 固定程序负责确定性计算。
2. 网页 GPT 负责理解当天动态信息。
3. 历史数据负责检验模型和 GPT 修正是否真的有效。
4. GPT 不直接修改核心 EV 公式、数据库历史、竞彩串关规则、资金约束和长期模型参数。
5. 允许 `NO BET`。没有价值的比赛不要为了凑单强行下注。
6. 系统是个人小资金娱乐与研究工具，不以自动下注为目标。

当前协作分工：

- **本聊天/网页 GPT**：主要负责每日赛事动态分析、赔率变化、阵容、天气、赛程、战意、比赛剧本、冷门和高赔率价值判断，并输出 `llm_review.json`。
- **另一个项目聊天**：主要负责系统架构、概率融合、EV、组合优化、资金模型、回测、Schema 与策略框架。
- **OpenCode**：主要负责本地 Python 工程的实现、测试、重构、Provider、数据库、CLI 和文件协作。
- **本地工程**：负责 `P_market / P_quant / P_final`、EV、奖金、串关展开、风险统计、压力测试和历史记录。

标准协作文件：

```text
analysis_packet.json
analysis_packet.md
llm_review.json
```

# 2. 用户的真实投注风格

用户是**小资金娱乐型**，不是传统“尽量提高命中率”的投注者。

最重要的偏好：

- 更喜欢 **中高赔率、高赔率和冷门**。
- 不希望推荐总是落在最低赔、最热门、最容易发生的结果上。
- 比起单纯“哪一个最可能”，更关心这个概率配这个赔率值不值得买。
- 如果一个结果从 10 倍变 20 倍，而真实概率没有下降一半，20 倍可能更值得买。
- 但从 20 倍变 30 倍，如果概率下降得更快，则仍然会选择 20 倍。
- 高赔不是越高越好，核心是**概率下降幅度和赔率上涨幅度的比较**。

基础价值公式：

\[
EV = p \times O - 1
\]

其中：

- `p` 是我们估计的真实概率；
- `O` 是实际竞彩固定奖金。

推荐不能只按概率排序，应至少区分：

1. **概率最高选择**
2. **赔率价值最好选择**
3. **高赔娱乐优选**
4. **冷门价值**
5. **矩阵容错备选**

# 3. 赔率使用规则

必须同时看：

- 中国竞彩 SP
- 欧洲指数
- 亚洲指数
- 国际大小盘口，用于理解市场进球预期
- 国际市场正确比分赔率
- 初盘到即时盘变化
- 临场变化
- 多公司共识与分歧

注意：

- **国际赔率**主要用于判断市场概率、市场变化和价格偏差。
- **竞彩固定奖金**用于实际下注收益、EV 和串关奖金计算。
- 不得混用。

特别关注：

- 持续降赔
- 持续升赔
- 突然退盘
- 升盘不降水
- 降盘但欧赔不支持
- 竞彩赔率明显低于国际市场
- 热门球队名气导致过热
- 市场与基本面冲突

低赔率并不自动等于“安全”。

# 4. 每场比赛必须考虑的动态因素

以后所有正式分析尽量检查以下信息。

## 4.1 主客场

- 主场胜率
- 客场胜率
- 主客场进失球
- 球场特点
- 主场氛围
- 是否特殊场地

## 4.2 旅行与体能

- 长途奔袭
- 跨国旅行
- 岛屿、高原、高温地区
- 连续客场
- 休息天数
- 三天一赛
- 周中欧战或杯赛
- 是否踢过加时或点球大战

## 4.3 阵容受损

特别重视：

- 门将
- 中卫
- 边后卫
- 防守型中场
- 核心前锋
- 主要创造者

不能只统计“伤了几个人”，必须判断伤的是谁。

后防线多人同时缺阵时，对强队零封概率、对手进 1 球概率以及 3-0 / 3-1、4-0 / 4-1 等比分结构有直接影响。

## 4.4 天气和场地

关注：

- 高温
- 低温
- 暴雨
- 强风
- 雷雨
- 湿滑草地
- 人工草
- 场地积水

天气只能作为修正因素，不能单独决定比赛。

## 4.5 教练

关注：

- 战术特点
- 高位压迫或低位防守
- 临场调整
- 换人习惯
- 新教练上任
- 教练是否轮换
- 是否更重视杯赛或联赛

## 4.6 战意和赛程优先级

重点判断：

- 联赛争冠
- 保级
- 欧战资格
- 杯赛
- 亚冠、欧冠、欧联
- 次回合已有明显领先
- 即将到来的关键比赛
- 是否可能轮换

## 4.7 吃牌与裁判

关注：

- 球队吃牌率
- 关键球员犯规率
- 停赛风险
- 裁判场均黄牌
- 红牌
- 点球
- 是否对高对抗比赛影响明显

红牌、点球等属于高方差事件。不能把“强队穿盘”当成接近确定事件。

## 4.8 近期数据

- xG
- xGA
- 射门
- 射正
- 禁区触球
- 定位球
- 转换进攻
- 主客场近期表现
- 近期比分不能只看结果，要看过程质量

# 5. 深层比赛剧本与利益关系

韩国、沙特、卡塔尔、阿联酋、部分东欧和资本关系复杂的小联赛，可以增加一层“深层比赛剧本”分析。

需要核查：

- 实际控制人
- 关联股东
- 共同母公司
- 国资体系
- 共同主要赞助商
- 同集团多俱乐部
- 大量租借关系
- 长期转会网络
- 教练和管理层历史关系
- 地方政府关系
- 积分形势
- 一方是否明显更需要分数
- 双方是否存在互利结果
- 临场首发是否异常
- 盘口是否出现无法用基本面解释的异常

必须区分：

### 有公开依据的关系

可以纳入“利益关系/动机风险”。

### 没有证据的所谓默契球

不能直接当事实。

禁止因为赞助商相同、老板认识、租借过球员或地方关系就无证据断言操纵比赛。

建议使用证据等级：

- A：官方股权、官方公告、注册信息
- B：可信媒体、多来源验证
- C：间接关系
- D：论坛传闻，不进入概率修正

# 6. 事实、分析和推测必须分开

正式分析中要明确区分：

### 事实

例如：

- 某中卫停赛
- 某球队 72 小时前踢了 120 分钟
- 亚洲盘从 -1 退到 -0.75

### 分析

例如：

- 后防完整性下降，零封概率降低
- 市场对主队信心减弱

### 推测

例如：

- 主队可能为三天后的欧战轮换

不能把推测写成事实。

# 7. 比分玩法的核心规则

用户非常喜欢正确比分，但不能只推荐最低赔比分。

例如：

```text
2-0  5.5
3-0  8.5
3-1  11
4-0  16
```

即使 2-0 最可能，如果 3-1 的概率只下降一点，而赔率增加明显，3-1 可能更值得买。

每场比分建议尽量包含不同比赛剧本：

### 概率支撑比分

例如：

```text
2-0
```

### 赔率价值比分

例如：

```text
3-1
```

### 高赔率尾部

例如：

```text
4-1
5-1
```

高赔率尾部只能小额。

强热门比分不要全部押“零封”。应同时考虑：

```text
3-0 / 3-1
4-0 / 4-1
```

而不是：

```text
3-0 / 4-0 / 5-0
```

原因是过去复盘中多次出现强队大胜但弱队仍打进 1 球，因此“对手进一球分支”非常重要。

---

# 8. 总进球玩法

用户所在竞彩玩法使用：

```text
0球
1球
2球
3球
4球
5球
6球
7+球
```

不要直接让用户购买“大小球”或“双方进球”。国际大小球市场可以用于判断概率，但最终给用户的投注选择要转换成竞彩可买的总进球数。

总进球同样不能只选最低赔档。

例如：

```text
3球概率 25%，SP 3.6
4球概率 20%，SP 5.5
5球概率 12%，SP 9
```

则赔率价值排序可能是：

```text
4球 > 5球 > 3球
```

---

# 9. 强热门的处理方式

不能只因为主胜 1.20 就认定适合做胆，必须结合亚洲盘口深度。

例如：

```text
主胜 1.30 + 亚洲 -1
```

与：

```text
主胜 1.20 + 亚洲 -2.25
```

对应的净胜球概率完全不同。

强热门应分析：

- 普通胜
- 刚好赢 1 球
- 赢 2 球以上
- 高比分尾部

并且不要让大量资金都依赖 4-0、4-1 这种具体结果。

---

# 10. 信号冲突

如果：

- 欧赔认为主队明显热门
- 量化模型认为双方接近
- 主队近期状态差
- 亚洲盘支持不足
- 客队赔率很高
- 基本面支持客队

那么该场应标记：

```text
SIGNAL_CONFLICT
```

这类比赛不能因为主胜只有 1.6 就自动进入信心串。

它可能：

- 放弃
- 进入冷门池
- 使用受让
- 使用平局
- 使用高赔比分

过去波鸿一场就是重要教训：市场把波鸿做成热门，但模型和其他信息支持客队冷门，最终奥斯纳 0-1 取胜。以后不能一边识别到冷门价值，一边又把低赔热门放入主信心票。

# 11. 对冲的准确含义

这是整个资金设计里最重要的用户偏好之一。

用户所说的“对冲”不是：

> 用大量低赔率选项强行保本金。

而是：

> **高赔率主攻 + 小额反向/相邻高赔率保护。**

例如主票：

```text
A队让胜 × B场高价值方向
总赔率 8 倍
```

另一张票可以：

```text
A队让平 × C场高价值方向
总赔率 9 倍
```

或者：

```text
A队不胜比分 × C场高价值方向
```

两张都保持中高赔率。

目标不是所有结果都保本，而是：

- 主剧本命中，一张票可以明显盈利；
- 主剧本偏一档，相邻剧本票仍可能活；
- 避免一个核心判断错误导致全部票同时死亡。

这是“非对称高赔率对冲”。

---

# 12. 相邻剧本对冲

对冲重点不是购买极端反方向，而是保护**最可能击穿主判断的相邻结果**。

例如主判断：

```text
强队净胜2+
```

最危险相邻结果往往是：

```text
强队刚好赢1球
```

而不是直接：

```text
强队输球
```

主判断：

```text
强队难穿 -2
```

相邻保护可以是：

```text
强队2-0
强队3-1
让2球平
```

过去尤文一场是正面案例：主方向是“尤文让2球负”，同时保留“尤文2-0”比分。主方向失败时，2-0成为有效的相邻剧本保护。这种结构应保留。

---

# 13. 资金结构

用户不要求：

- 每次全部本金回收
- 每天必赚
- 每个赛果保本

更希望：

- 有较高机会拿到部分回款
- 偶尔 100 回 150～250
- 偶尔 200 回 300 左右
- 大奖交给概率和运气
- 不要因为一个核心判断错了导致整套 0 回款

用户不喜欢：

```text
70元买1.25低赔
剩下30元高赔
```

这种伪保本结构。

---

# 14. 最终票数和操作要求

最终：

```text
最多4张票
```

并且必须**好操作**。

优先：

```text
2串1
3串4
4串11
简单复式
```

避免：

- 手动拆十几张票
- 不同金额的复杂矩阵
- 大量单关小分支
- 需要用户计算几十个组合

分析可以复杂，但最终下单必须简单。

最理想输出类似：

```text
单1：A + B + C，3串4，40元
单2：D + E，2串1，25元
单3：A相邻反向 + F，2串1，25元
单4：3个比分，10元娱乐
```

---

# 15. 用户当前最接受的典型结构

100 元并没有永久固定分配，但较符合用户的形式是：

### 主攻票

- 3串4
- 约 35～50 元
- 3 个真正有赔率价值的判断
- 错一场仍有 2 串 1

### 第二主攻

- 2串1
- 约 20～30 元
- 总赔率约 7～10 或 7～12 倍
- 单独命中可以有明显收益

### 反向高赔保护

- 2串1
- 约 15～25 元
- 对主攻中某个关键比赛使用相邻/反向剧本
- 与另一个独立价值场组合
- 本身仍然是中高赔率

### 娱乐票

- 约 8～15 元
- 几百倍、千倍、万倍均可
- 不能承担主要回本任务

这只是结构模板，不是必须每次机械套用。如果当天只有两场值得下注，可以只出两张票。

---

# 16. 7～10 倍是重要区间

用户很喜欢：

```text
2场高价值选择
×
总赔率 7～10倍
```

这种二串一。

原因：

- 20元左右投入
- 命中可以回 140～200 元
- 一张命中就可能接近回本甚至盈利
- 不需要串大量低赔

不要为了达到 7～10 倍强行塞没有价值的比赛。

---

# 17. 千倍/万倍娱乐票

用户喜欢保留一张高倍率娱乐票。

要求：

- 投入小
- 每一腿都应有一定比赛逻辑
- 不能为了凑 1000 倍强行塞 4-0、5-0
- 可以使用比分、总进球、半全场、冷门方向
- 可以用 3串4 提高两个比分命中的回报
- 大奖仅作为尾部，不承担回本任务

高倍率票应明确说明：

```text
这是低概率娱乐仓
```

---

# 18. 单场风险暴露与相关性

过去一个重大问题是：

> 看似买了很多张票，实际上都依赖同一场、同一个比分。

例如：

- 主票依赖多特4-0
- 比分票依赖多特4-0
- 千倍票依赖多特4-0
- 万倍票仍依赖多特4-0

这不是分散，是风险集中。

以后必须检查：

```text
某一场失败会同时杀死多少钱？
某一个比分失败会同时杀死多少钱？
```

任何一个具体准确比分不能成为大量资金的共同基础。

建议每次正式方案报告：

```text
match_exposure
scenario_exposure
```

---

# 19. 压力测试

最终出票前至少模拟：

### 情景1
第一核心场完全错误。

### 情景2
第一、第二核心场同时错误。

### 情景3
强热门赢球但只赢1球，没有穿盘。

### 情景4
比赛出现早早红牌或点球，导致比赛失控。

### 情景5
主比分只偏一个球。

需要回答：

- 哪些票仍然存活？
- 还有多少本金有机会产生返还？
- 是否所有主票都被同一个结果杀死？

如果两个中等概率核心错误后所有票全部死亡，则组合结构应重新设计。

# 20. 复盘教训

以下是本聊天已经形成的重要经验。

## 20.1 不要系统性低估强队大比分尾部

曾出现：

- 拜仁5-1
- 新月5-1
- 葡体0-4
- 曼城1-4

早期分析过度集中于3球和4球。

以后强热门深盘时应适当增加：

```text
4球
5球
6球
4-1
5-1
```

的权重，但只作为高赔尾部。

## 20.2 强队大胜时弱队进1球很常见

不能只做：

```text
3-0 / 4-0
```

应防：

```text
3-1 / 4-1 / 5-1
```

## 20.3 米兰2-0是盘口深度判断的正例

当：

- 1X2很低
- 亚洲盘只有 -1 / -1.25

则更应关注：

```text
2-0
2-1
```

而不是直接追：

```text
3-0
4-0
```

## 20.4 波鸿冷门是信号冲突的教训

不能因为主队赔率 1.6 就自动进入信心串。

## 20.5 格罗宁根2-3说明高节奏联赛要提高互攻比分

荷甲等比赛：

```text
2-2
2-3
3-2
```

不应被低估。

## 20.6 巴黎2-2说明豪门客场1.6～1.8并不稳

客场豪门必须重新评估：主客场差异、对手主场韧性、赛程、后防和让球深度。

## 20.7 多特红牌是高方差事件教训

强热门“穿盘”不是接近确定事件。大量票不能共同依赖让胜。

## 20.8 尤文2-0是有效相邻剧本保护

主方向：

```text
尤文让2负
```

相邻保护：

```text
尤文2-0
```

# 21. 历史资金结构复盘

本聊天中出现过几种典型 100 元结构。

## 21.1 复杂分散版

实际大约：

```text
100 -> 78.39
```

特点：

- 很多判断命中
- 但盈利效率低
- 操作复杂
- 过度追求回收

教训：

> 不能为了提高“有回款概率”牺牲赔率效率。

## 21.2 高赔30元×3版

实际：

```text
100 -> 0
```

特点：

- 三张高赔二串一
- 缺少相邻剧本保护
- 每张都需要两个高赔判断同时正确

教训：

> 不能从一个极端走到另一个极端。

## 21.3 3串4核心版本

实际大约：

```text
100 -> 240+
```

结构大致：

- 64元核心3串4
- 20元二串一
- 8元总进球3串4
- 8元比分3串4

其中核心3串4三个判断全部命中，成为主要盈利来源。

教训：

> **有赔率价值的3串4 + 少量独立高赔票** 是目前最值得继续发展的结构之一。

但 64 元压一张3串4仍略重，未来可以适度降到40～50元。

## 21.4 另一套早场

实际：

```text
100 -> 120.89
```

主要靠一个16元3串4完整命中和另一个二串一。

教训：

> 不需要所有票都中。一张赔率结构优秀的容错主票就有机会托住整晚。

# 22. 用户真正希望的收益分布

用户并不要求平均返还最大。

例如：

```text
期望返还80元
```

并不是用户最关心的结果。

更关心：

```text
P(return >= 100)
P(return >= 150)
P(return >= 200)
P(return >= 300)
P(return very large)
P(return near zero)
```

尤其希望：

- 2～3张20元左右中高赔单
- 任意一张命中就有机会接近回本或盈利
- 高赔率单之间有剧本保护
- 少量大奖尾部

本地工程以后应计算：

```text
P(return > 0)
P(return >= budget)
P(return >= 2*budget)
P(return >= 3*budget)
P(return <= 0.2*budget)
median_return
expected_return
```

而不只算 EV。

# 26. 重要禁止事项

以后不要：

1. 因为赔率最低就自动推荐。
2. 因为赔率最高就自动推荐。
3. 把多个不同票全部建立在同一个具体比分上。
4. 为了“保本”大量购买1.2～1.5低赔率。
5. 为了凑千倍强行选离谱比分。
6. 为了每天必须出4张票而下注。
7. 无证据推断默契球。
8. 忽略首发、伤停、旅行和天气。
9. 用复杂数学结构导致实际下单非常困难。
10. 一场失败后追损追加。

# 27. 推荐时的语言规则

对于每一个重点选择最好给：

```text
赔率价值
风险
推荐定位
```
