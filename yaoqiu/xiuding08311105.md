现有“本地工程与网页 GPT 文件协作桥”方案确认采用，但在实现前请做以下架构修订。

1. 不允许导入 LLM Review 后修改原始 AnalysisRun。

AnalysisRun 必须继续保持 append-only 和 immutable。

新增概念：

LLMReviewArtifact
FusionRun
PortfolioRevision

LLMReviewArtifact 通过 parent_analysis_run_id 引用原始 AnalysisRun。

FusionRun 保存 P_base、P_llm、实际应用的概率修正、P_final、融合策略版本和降级状态。

重新优化得到新的 PortfolioRevision，而不是覆盖原 Portfolio。

2. LLMReview 优先返回绝对概率 P_llm，而不是只返回 probability_delta。

建议：

p_llm:
home_win
draw
away_win

本地程序根据：

P_llm - P_base

计算 raw probability delta。

然后根据：

confidence
data_quality
evidence reliability
LLM adjustment config

进行 clipping 和 scaling。

GPT 不拥有直接覆盖 P_final 的权限。

3. 第一轮 Web GPT Match Review 不应看到最终资金配置。

用于上传给 Web GPT 的 Review Context 中删除：

current_portfolio
stake
budget
最终 Ticket
最终 EV 排名

避免 LLM 被现有投注结果锚定。

如果以后需要网页 GPT 检查组合结构，建立独立的：

PortfolioReviewPacket

Portfolio Review 只能评价组合结构，不允许重新修改 P_llm。

4. 将 hedge_candidates 改成语义级：

counter_scenarios

或者：

hedge_suggestions

LLM 可以表达：

主剧本失败后最可能的相邻或反向剧本。

但是 LLM 不直接决定这个方向必须投注。

Betting Engine 必须继续使用 P_final、竞彩 SP、EV 和 Portfolio Constraint 判断是否创建 HEDGE。

5. Evidence 统一采用已有架构中的字段设计，至少包括：

evidence_id
category
claim
source_reference
source_type
published_at_utc
observed_at_utc
available_at_utc
confirmation_status
reliability_level

所有由 Web GPT 新查询得到的信息也必须形成 Evidence。

6. AnalysisPacket 增加：

packet_id
generated_at_utc
packet_hash

LLMReview 必须回传：

analysis_run_id
packet_id
packet_hash

导入时全部严格验证，避免 Review 与错误的数据包匹配。

7. relationship_evidence 可以保留，但默认只作为语义 Evidence。

资本、母公司、赞助、政府、租借、转会等关系本身不能直接推导比赛结果或默契行为。

必须记录事实来源和 reliability。

只有有明确、可验证且与比赛相关的证据时，才能通过 LLM Assessment 间接影响 P_llm。

8. 第一版压力测试只实现可以确定性计算的场景：

最高风险暴露比赛主方向失败
风险暴露最高两场同时失败
热门球队只赢但未穿让球
主胜变平
主胜变负
准确比分未命中
LONGSHOT 全部失败

每个 StressScenario 输出：

存活 Ticket
死亡 Ticket
portfolio gross return
portfolio profit/loss
capital recovery ratio
single-match exposure
single-scenario exposure

红牌、点球和早失球等动态事件暂时只保留接口，不在第一版建立伪精确概率模型。

9. Strategy Profile 增加 LONGSHOT 约束，例如：

longshot:
enabled: true
max_ticket_count: 1
max_budget_ratio: 0.10

具体值必须可配置。

LONGSHOT 作为娱乐性尾部收益票，不参与所谓保本设计。

10. 本次任务的核心仍然只是建立最小文件协作闭环。

不要因为加入上述接口而提前实现复杂 Agent、MCP、真实自动调用 ChatGPT、多 Agent 或自动下注。

先完成：

Base AnalysisRun
→ AnalysisPacket
→ LLMReviewArtifact
→ FusionRun
→ P_final
→ Betting Engine
→ PortfolioRevision
→ StressTest

并确保全流程具有 pytest 和可回放记录。

请先基于以上修订更新本次任务设计，再提交文件清单、Schema、CLI 和数据流，不要立即开始全部编码。
